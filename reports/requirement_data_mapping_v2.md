# 需求—数据映射 v2.0（通俗版）

**一句话**：比赛要考什么 → 我们需要准备什么数据 → 用什么指标打分 → 数据从哪来

---

## 一、六项指标，一句话说清楚

### 1. 偏好提取 — 模型能不能记住用户的喜好？

**场景举例**：
```
用户说："以后周报用要点，不要长篇大论。"
→ 模型应该记住这个偏好，下次写周报时自动用要点格式。
```

**我们需要的数据**：
- 用户说了什么偏好（输入）
- 偏好是什么类型（输出风格/工具选择/作用域等）
- 偏好范围（全局/仅当前会话/仅某个应用）
- 是否要记住（存/不存）

**打分方式**：Precision（猜对的/猜的总数）、Recall（猜对的/应该猜的总数）、F1（综合分）
**及格线**：F1 >= 85%
**数据从哪来**：自建为主（60 条候选，目标 400~500 条）

---

### 2. 知识检索 — 模型能不能找到正确的信息？

**场景举例**：
```
用户问："麒麟OS安装失败排查步骤是什么？"
→ 模型应该从知识库中找到正确的文档。
```

**我们需要的数据**：
- 用户问了什么问题（查询）
- 这个问题对应的正确答案是哪些文档（相关文档 ID）
- 哪些文档看起来相关但其实是错的（困难负样本）
- 正确答案应该包含哪些要点

**打分方式**：Recall@K（前 K 个结果中找对了几个）、MRR（第一个正确答案排第几）、nDCG（排序质量）
**及格线**：Recall@5 >= 85%
**数据从哪来**：T2Ranking/DuReader 辅助 + 自建麒麟 OS 知识库（60 条候选，目标 300~400 查询 + 600~1000 知识条目）

---

### 3. 冲突处理 — 新旧信息矛盾时，模型能不能正确处理？

**场景举例**：
```
用户先说："默认使用 Chrome 浏览器。"
用户后来说："以后用 Firefox。"
→ 模型应该知道新覆盖旧，记住 Firefox，忘掉 Chrome。
```

**我们需要的数据**：
- 旧信息是什么、新信息是什么（冲突双方）
- 谁赢了（新覆盖旧 / 按来源优先级 / 按作用域）
- 冲突类型（时间/来源/作用域/版本/安全）

**打分方式**：准确率（答对的 / 总题数）
**及格线**：>= 88%
**数据从哪来**：自建为主（40 条候选，目标 200~300 条）

---

### 4. 精准遗忘 — 用户让删的东西，模型能不能真的忘掉？

**场景举例**：
```
用户说："把我之前设置的 VSCode 主题偏好删掉。"
→ 模型应该删掉 VSCode 主题，但保留其他编辑器偏好。
```

**我们需要的数据**：
- 要删什么（目标 ID）
- 哪些是不能删的（必须保留）
- 删完后检查（立即查/重启后查/重建索引后查）

**打分方式**：
- 删除正确率（该删的删了没）>= 95%
- 误删率（不该删的删了没）<= 5%
- 残留数（删完后还能查到吗）= 0

**数据从哪来**：必须自建（40 条候选，目标 150~250 条）

---

### 5. Tool Result — 模型执行工具操作后，能不能正确判断结果？

**场景举例**：
```
用户让模型删除文件 → 模型执行删除命令 → 成功/失败/超时/部分成功
→ 模型应该正确判断操作结果并记录下来。
```

**我们需要的数据**：
- 执行了什么工具（文件管理器/终端等）
- 结果是什么（成功/失败/取消/超时/部分成功）
- 是否有副作用（比如删文件时连带删了其他东西）

**打分方式**：状态判定准确率 >= 90%
**数据从哪来**：必须在麒麟虚拟机真实执行（当前 0 条，目标 200~300 条）

---

### 6. 端到端会话 — 多轮对话后，模型能不能记住上下文？

**场景举例**：
```
第 1 次对话：用户设置"周报用要点格式"
第 2 次对话（重启后）：用户说"写周报"
→ 模型应该记得用要点格式，而不是长篇大论。
```

**我们需要的数据**：
- 完整的对话历史（多轮、跨会话）
- 期望模型记住什么（记忆预期）
- 期望模型回答什么（回答预期）

**打分方式**：响应匹配率 >= 80%
**数据从哪来**：麒麟环境生成（15 条候选，目标 50~80 条）

---

## 二、计算方法与算法（技术版）

### 1. 偏好提取准确率（目标 F1 >= 85%）

**需准备的数据**：显式/隐式偏好、非偏好负例、作用域、版本更新、冲突样本

**公式**：
```
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1        = 2PR / (P + R)
```

**算法**：系统输出的偏好条目与 Gold 偏好条目做键匹配（键 = user_id + 偏好类型 + 对象 + 作用域 + 值），统计 TP/FP/FN。
- 非偏好负例用于检验误报（FP）
- 自由文本的偏好值无法精确匹配时，用 LLM Judge 判等价（**规则匹配优先**）

**注意**：必须按偏好类型 × 场景分组报告，只报总 F1 不合格。

---

### 2. 知识检索召回率（目标 Recall@K >= 85%）

**需准备的数据**：查询集 + 每查询的 relevant_ids + 困难负样本

**公式**：
```
Recall@K = |检索前 K 条 ∩ Gold 相关| / |Gold 相关|
```
逐查询计算后取**宏平均**。

**辅助算法**：
- MRR：首个相关文档排名倒数的均值
- nDCG@K：带位置折扣的增益
- Recall = 0 的失败查询单独归因分析

**注意**：以 Recall@K 为主指标，MRR/nDCG 只作辅助。

---

### 3. 知识检索响应时间（目标 P50/P95 <= 500ms）

**需准备的数据**：固定语料规模、固定查询集、冷启动/热启动记录

**算法**：同一查询集多次运行，取延迟的 P50/P95/P99 分位数；同时记录硬件、索引状态、缓存条件。

**注意**：单次延迟不能当稳定指标；冷启动与热启动必须分开报。

---

### 4. 知识冲突处理正确率（目标 >= 88%）

**需准备的数据**：新旧版本、来源冲突、作用域冲突、时间冲突、保留/覆盖预期

**公式**：
```
准确率 = 预测决策与 Gold 决策一致的组数 / 总冲突组数
```

**算法**：逐冲突组比对预测动作（保留旧 / 覆盖新 / 合并 / 拒绝）与 Gold 决策；错误必须按冲突类型归类输出（哪类冲突失败最多）。

---

### 5. 精准遗忘（功能要求：删除正确率 + 残留率 = 0）

**需准备的数据**：删除目标、应保留对象、敏感字段、索引重建后的残留检查

**三个指标**：
```
删除正确率 = 正确删除的目标数 / 全部删除目标
误删率     = 被误删的应保留对象数 / 全部应保留对象
残留数     = 重建后仍可检索到的已删对象数（要求为 0）
```

**算法**：在三个时点检查：
1. 删除后即时查询
2. 重启后查询
3. 索引全量重建后查询

查询手段包括直接检索和语义相近查询（防"换个问法又搜出来"）。

---

### 6. 端到端任务完成率 + 延迟（含 Tool Result 状态准确率）

**需准备的数据**：跨会话真实操作链（麒麟虚拟机回放日志）

**完成率**：任务终态与 Gold 终态一致（含中间检查点）的会话数 / 总会话数

**延迟**：P50/P95/P99，冷/热启动分开，<= 500ms

**Tool Result 状态准确率**：每次工具调用预测的 status（成功/失败/取消/超时/部分成功）与 Gold 标注一致的比例

---

## 三、通用评测纪律（手册硬性要求）

1. **判分优先用规则/集合比对**，LLM Judge 仅用于自由文本等价性判断，且必须归档 Judge Prompt、模型版本、温度和多次运行结果
2. **公开数据集的原始指标不得直接算本项目成绩**——必须经统一 Schema 转换后走本系统完整管线
3. **正式评测必须离线可复现**，不依赖在线 API 实时成功率
4. **报告中每个数字必须能回溯到原始结果文件**

## 五、下一步优先做什么

1. **最紧急**：Tool Result 数据为 0，需要麒麟 VM 到手后立刻执行
2. **最耗时**：知识库搭建（600~1000 条），需要麒麟 OS 技术文档
3. **最基础**：偏好/冲突/遗忘从候选扩到目标量，需要设计更多模板
4. **等条件**：端到端会话需要麒麟 VM 环境
