# v4.1 G2 scope 人工复核标准（Data-A）

- 角色：Data-A（lyf-1213）
- 版本：v4.1
- 依据：KMA Canonical 5.8 `preference_scope ∈ {global, topic, tool, session, time_window}`；v4.1 台账 10_任务判定矩阵 / 11_Admission G2（人工 100% 确认）；v4 gap_fix_plan G2。
- 目的：进入正式 Gold 的 Preference 候选，逐条人工判定 scope；**禁止默认 tool**；不确定 → `NEEDS_REVIEW`。

## 一、判定顺序（对每条候选）

1. 该偏好是**未来持续/重复**，还是**仅本次约束**？
   - 仅本次 → `session`（或临时偏好，is_temporary=true）
2. 指向对象：
   - 针对**某个具体应用/工具**的行为（项目管理工具、邮件客户端）→ `tool`
   - 针对**某类工作主题**（周报、代码评审、装修）→ `topic`
   - **整体系统/默认行为**（以后都先问我确认）→ `global`
   - **本次会话/本次请求** → `session`
   - **某时间窗**（本月、项目期间）→ `time_window`
3. 无法仅凭文本确定对象 → `NEEDS_REVIEW`，不猜。

## 二、禁止项

- 不得机械默认 `tool`（旧映射"周报→tool"已废弃）。
- app≠tool、task≠topic 必须按语义裁决，不得直接套用旧 scope 名。
- 不得用 `active/v1` 等默认业务真值补 Schema。
- 敏感/不可存储偏好：判定 negative / blocked by policy，不判 scope 后入库。

## 三、scope 判定速查（供 A 标注时对照）

| 用户表达 | 判定 |
| --- | --- |
| 以后每周报告都用要点 | topic（针对报告主题） |
| 这个项目管理工具里用中文标签 | tool（针对具体工具） |
| 以后都先问我确认 | global（整体默认） |
| 这次就按英文回复 | session（仅本次） |
| 项目期间用英文回复 | time_window（有明确时间窗） |
| 发邮件时默认带签名 X | tool（邮件客户端行为） |
| 做周报时用简洁要点 | topic |
| 某个具体工具 vs 助手整体 | 工具唯一确定→tool；助手整体→global 或 NEEDS_REVIEW |

## 四、输出与闭环

- 产出：scope_review 清单（每条 candidate 一行：sample_id / proposed_scope / reviewer(A) scope / NEEDS_REVIEW? / reason）。
- 修正 SCOPE_MAP 并加断言测试（B 复核）。
- 验收：断言测试 exit 0；NEEDS_REVIEW 全部有后续判定。

## 五、与其他 Gate 关系

- G2 Semantic（A/B 确认）→ 本清单作为 A 侧语义+scope 确认输入。
- 与 KMA 5.8 保持一致；若主仓 M1 冻结后 enum 有变，以冻结版为准并回溯。
